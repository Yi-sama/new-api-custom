# 2026-09-20

## Auto 模型

- 复用原有模型广场“全部分组”筛选，不新增虚拟 API 分组；Auto 作为特殊模型按实际命中的模型、分组和渠道倍率计费。
- 新增特殊模型 `Auto`，支持 `/v1/chat/completions` 与 `/v1/responses` JSON 请求。
- 用户可在模型广场的 Auto 详情中自由选择候选模型，并选择“低倍率优先”或“模型顺序优先”；策略下方常显说明，用户修改后可恢复默认。
- Auto 会跳过当前无可用渠道的候选模型；跨模型重试会重新计算预扣费，并清除上一模型遗留的阶梯计费快照。
- Auto 用户设置改为数据库事务内合并指定字段，避免覆盖并发更新的通知、语言等其他设置。
- API Key 分组选择继续使用原有真实分组，不新增“全模型”API 分组；Auto 复用已有 `auto` token group 机制。
- 管理员站点默认模型位于“额外设置 → Auto 默认设置”，只维护默认模型列表，不新增分组显示开关。
- 用户和管理员的已选模型列表均提供逐行移除按钮；本功能新增界面文案使用中文，仅保留 `Auto` 和模型 ID 原文。
- 修复 Auto 详情在无候选模型时读取 `null.length` 的崩溃：后端空模型列表固定返回 `[]`，前端 API 边界同时兼容历史 `null` 响应。
- 修复 Auto 候选为空的根因：当站点未单独配置 `AutoGroups` 时，自动回退到用户可用的全部真实分组，并按分组倍率从低到高生成组顺序；因此站内默认模型会按真实能力表显示，策略排序也能找到实际渠道。
- 进一步修复旧库兼容：旧库没有 `AutoGroups` 记录时会加载内置 `default`，但用户实际可用分组为 `1`、`group_1` 至 `group_5`；现在当已配置/默认 AutoGroups 过滤后为空时同样触发全部可用分组回退。运行时已验证用户 1 返回 13 个允许模型，默认列表返回 2 个模型。

## Auto 按 API Key 分组作用域

- API Key 的特殊分组值继续复用 `auto`，界面统一显示为“所有分组”和“动态倍率”；未新增数据库分组、字段或迁移。
- “所有分组”API Key 的 Auto 按该 Key 的授权分组顺序跨组选择；普通固定分组 API Key 的 Auto 候选模型严格限制在该固定分组内。
- `/v1/models` 对有可用模型的普通固定分组也返回 `Auto`；Anthropic 与 Gemini 专用模型列表仍不返回 Auto。
- 模型广场中的 Auto 现在归属用户可用的每个真实分组，因此选择任一分组筛选时都能看到 Auto；实际请求仍按 API Key 分组权限选择。
- 模型白名单继续过滤 Auto 的真实候选模型，不会因虚拟 Auto 模型绕过权限。
- API Key 创建/编辑下拉和密钥列表统一显示“所有分组 + 动态倍率”，底层仍保存兼容旧库的 `group: "auto"`。
