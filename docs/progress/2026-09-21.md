## API Key 模型限制支持 Auto

- 症状：新增或编辑 API Key 时，“模型限制”下拉只显示真实模型，无法单独授权虚拟模型 `Auto`。
- 根因：模型限制选项直接使用后端真实模型列表；`Auto` 是运行时虚拟模型，不在该接口结果中，因此固定分组密钥无法选中它。
- 修复：模型限制选项固定加入一次 `Auto` 并去重；保存时把 `Auto` 作为独立权限项，不要求同时授权其内部候选真实模型。
- 请求鉴权改为检查客户端原始请求模型。请求 `Auto` 时先校验密钥是否允许 `Auto`，再按用户配置、API Key 分组和渠道能力选择真实模型。
- 普通固定分组的 Auto 候选仍严格限制在该分组内；“所有分组”密钥才可按授权分组范围跨组选择。
- `/v1/models` 同步按独立权限返回 `Auto`，不会因只授权 `Auto` 而泄露未授权的真实模型。

## Redis NOSCRIPT 限流故障永久修复

- 根因：`common/limiter/limiter.go` 只在进程启动时执行一次 `SCRIPT LOAD`，之后始终使用进程内保存的 SHA 调用 `EVALSHA`。Redis 重启或脚本缓存丢失后，限流持续返回 `NOSCRIPT`，中间件将其转换为 HTTP 500 `rate_limit_check_failed`。
- 上游 Issue `#6412` 明确建议在 `NOSCRIPT` 时重载并重试一次，或使用 go-redis `Script.Run` 自动回退到 `EVAL`。关闭未合并的 PR `#2856` 还包含无关的滑动窗口重构，因此没有整体移植。
- 最小修复：使用当前已锁定的 go-redis v8.11.5 `redis.NewScript(...).Run(...)` 替代手工 `ScriptLoad` 和永久保存 SHA；新增 miniredis 回归测试，覆盖首次限流成功、`SCRIPT FLUSH`、同一进程再次限流自动恢复。
- 验证：`go test ./common/limiter -count=1`、中间件编译检查、`go build ./...` 和 Linux amd64 静态构建均通过；独立只读审查无上线阻断项。
- 美国服务器发布版本为 `v1.0.0-rc.28-custom-e468b739-auto-noscript-20260921`，路径 `/opt/proxy/newapi/releases/20260921-1838-noscript-e468b739/new-api`，SHA-256 `7f73d7b516cde46e94a40c715a27dde4519626a21c3016efe9f507b2e1206179`。
